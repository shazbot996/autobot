## About a context singleton

A context singleton is one document about one subject, kept under `docs/context/` and maintained in
place: never numbered, never superseded, only ever brought up to date. The core rows' squares are
singletons with a fixed job each; this is the general case, for a subject the core set did not
anticipate.

**Its authority is its own.** A singleton declares whether it describes the code or prescribes to it,
and that declaration decides everything else. Read it before acting, and act in the direction it
names.

**It belongs here:** one subject, treated completely enough that a reader does not need a second file
on the same thing. If a second singleton on the same subject seems needed, the first one is either
too narrow or wrongly named.

**It does not belong here:** anything with a history of its own (a decision), anything that is a
behaviour to be built (a spec), or anything that will be obsolete when a piece of work lands (a plan).

**The failure to avoid** is sprawl. A singleton is edited in place for its whole life, and a document
edited for years accretes. Prefer rewriting a section so it is true now over appending a paragraph
that qualifies the one above it.
