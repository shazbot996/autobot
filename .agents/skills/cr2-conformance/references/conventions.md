## About a conventions document

Conventions say how work is done here. They are **prescriptive**: work that does it differently is
wrong, until the convention is changed deliberately and the change is recorded.

**Every convention carries its reason.** "Specs are numbered rules" is a habit. "Specs are numbered
rules, because a rule you can cite is a rule you can be held to" is a convention, and the reason is
what tells a reader whether a new case falls under it.

**It belongs here:** naming, the shape of each kind of document, how changes of each size are
recorded, spelling and voice, how code is laid out when the tree does not make it obvious, and the
test for when a thing needs a spec, a decision, a plan, or nothing at all.

**It does not belong here:** rules an automated tool already enforces (the tool is the convention),
architecture (ARCH), or anything that is really a constraint on what the system may do rather than on
how people work (CONSTRAINTS).

**The failure to avoid** is aspiration. A convention nobody follows is not a convention, it is a
wish, and writing it down makes every other line less credible. Record what is done, and when you
want to change what is done, say so as a change.
