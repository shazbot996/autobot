## About a README

A README is the front door: the first thing a person reads when they arrive at the repository, and the
thing a forge renders to anyone who never opens another file. It is **descriptive**. The repository is
the truth, and a README that disagrees with it is stale and wrong.

**It answers three questions, in this order.** What is this, in a paragraph a stranger can follow. How
do I run it, as commands that work when pasted. Where is everything else, as a map of the documents
rather than a copy of them.

**It belongs here:** the one-paragraph purpose, the commands to install and run, the settings a
newcomer must provide, a table of where the documents live, and an honest status line saying what
works and what does not.

**It does not belong here:** architecture (that is ARCH), rules for contributors (CONVENTIONS),
instructions to agents (AGENTS), design rationale (the decisions), or a feature list longer than the
reader's patience. A README that tries to be every document is none of them, and it is the first to
go stale because it restates everything.

**The failure to avoid** is marketing. Adjectives are not information. "A powerful, flexible tool"
says nothing a reader can act on; "reads markdown under docs/ and draws one square per document"
says something they can check.
